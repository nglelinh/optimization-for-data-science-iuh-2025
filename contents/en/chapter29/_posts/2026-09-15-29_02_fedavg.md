**Federated averaging** (McMahan, Moore, Ramage, Hampson, y Arcas, AISTATS 2017) repeats:

1. The server broadcasts the current global model $$w_t$$ to a subset of clients $$\mathcal{S}_t$$.
2. Client $$c\in\mathcal{S}_t$$ runs $$E$$ local epochs of SGD on its *private* data, producing $$w_{t+1}^{(c)}$$.
3. The server sets

$$
w_{t+1} = \sum_{c\in\mathcal{S}_t} \frac{n_c}{n_{\mathcal{S}_t}} w_{t+1}^{(c)},
$$

where $$n_c$$ is the client’s example count and $$n_{\mathcal{S}_t}=\sum_{c\in\mathcal{S}_t}n_c$$.

If $$E=1$$ and each client takes one step on the *same* global batch size story, FedAvg collapses toward ordinary data-parallel SGD. The interesting (and statistically harder) regime is $$E>1$$: local drift on **heterogeneous** (non-IID) client distributions. Communication rounds become the iteration index that matters.

```python
def fedavg_round(global_w, client_updates, client_sizes):
    n = sum(client_sizes)
    acc = 0.0
    for w_c, n_c in zip(client_updates, client_sizes):
        acc = acc + (n_c / n) * w_c
    return acc
```

**Why devices.** Privacy, regulation, and bandwidth: you cannot ship every phone’s photos to a datacenter every night. FedAvg is a *pattern*, not a privacy proof — gradients and weights can still leak. Formal privacy (DP-SGD, secure aggregation) is a different course.

**Exercise.** Partition a tiny MNIST (or even a 2-D Gaussian mixture) across 3 clients that each see only one class. Run FedAvg with $$E=1$$ vs $$E=5$$. Watch the global model oscillate when local steps overfit the missing classes.
