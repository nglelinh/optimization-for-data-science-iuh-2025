In 2017, Brendan McMahan and colleagues at Google faced a constraint that broke standard distributed ML: improving mobile keyboard next-word prediction across millions of smartphones *without ever uploading a single user’s raw text to the cloud*. Their answer—**Federated Averaging (FedAvg)**—flipped data-parallel SGD on its head: send the model to the data, let a sampled subset of phones run multiple local epochs of SGD, and average only the resulting weight updates back on the server. When client data is IID, FedAvg saves orders of magnitude in communication; when client data is non-IID, however, multiple local steps introduce a fascinating failure mode called **client drift**.

## Background Knowledge Map: Mechanics and Failure Modes of FedAvg

- **The Four-Step FedAvg Round:** (1) Server samples a small fraction $$\mathcal{S}_t$$ of clients (partial participation), (2) broadcasts $$w_t$$, (3) each client runs $$E$$ local SGD steps on its private dataset $$F_c$$, and (4) server forms the data-weighted average $$w_{t+1} = \sum_{c \in \mathcal{S}_t} \frac{n_c}{n_{\mathcal{S}_t}} w_{t+1}^{(c)}$$.
- **Special Case $$E = 1$$ Recovers Data-Parallel SGD:** When every client takes only 1 local step with identical step size $$\eta$$, averaging the resulting weights $$w_t - \eta g_c$$ is algebraically identical to averaging gradients!
- **Client Drift Under Non-IID Heterogeneity:** When $$E > 1$$ and clients have distinct local minimizers $$w_c^\star \ne w^\star$$, local SGD pulls each client toward its own $$w_c^\star$$. Averaging those drifted models does *not* generally equal the global optimum $$w^\star$$—even with exact local gradients and zero sampling noise!
- **Partial Participation & System Heterogeneity:** Because mobile clients drop offline and have wildly varying compute speeds, FedAvg samples a fresh subset $$\mathcal{S}_t$$ each round, introducing an extra layer of client-sampling variance on top of local minibatch noise.

### Step-by-Step Worked Example (Read Slowly): Seeing Non-IID Client Drift in Exact Closed Form

Consider $$P = 2$$ equal-weight clients minimizing $$F(w) = \frac{1}{2}\bigl(F_1(w) + F_2(w)\bigr)$$ where:
- Client 1 has steep local loss $$F_1(w) = \frac{1}{2}\cdot 4(w - 1)^2 = 2(w - 1)^2$$ (local optimum $$w_1^\star = 1$$).
- Client 2 has flat local loss $$F_2(w) = \frac{1}{2}\cdot 1(w + 1)^2 = \frac{1}{2}(w + 1)^2$$ (local optimum $$w_2^\star = -1$$).

1. **Find the true global optimum $$w^\star$$:**
   $$F'(w) = \frac{1}{2}\bigl[4(w - 1) + (w + 1)\bigr] = \frac{5w - 3}{2} = 0 \implies w^\star = \frac{3}{5} = 0.6.$$
2. **Run FedAvg with large local steps ($$E \to \infty$$, exact local minimization) starting right at the true optimum $$w_0 = 0.6$$!**
   - Client 1 runs local GD to its own optimum: $$w_1^{(1)} = 1.0$$.
   - Client 2 runs local GD to its own optimum: $$w_1^{(2)} = -1.0$$.
   - Server averages them: $$w_1 = \frac{1.0 + (-1.0)}{2} = 0.0 \ne 0.6$$!
3. **Check finite $$E = 2$$ with $$\eta = 0.2$$ starting at $$w_0 = 0.6$$:**
   - Client 1 ($$w \leftarrow w - 0.8(w - 1) = 0.2 w + 0.8$$): $$0.6 \to 0.92 \to 0.984$$.
   - Client 2 ($$w \leftarrow w - 0.2(w + 1) = 0.8 w - 0.2$$): $$0.6 \to 0.28 \to 0.024$$.
   - Server average: $$w_1 = \frac{0.984 + 0.024}{2} = 0.504$$!
   Even starting at the *exact* global optimum $$w^\star = 0.6$$, FedAvg with $$E = 2$$ immediately **drifts away** to $$0.504$$ (and converges to a biased fixed point $$w_{\text{FedAvg}} \ne 0.6$$)—demonstrating concretely why non-IID heterogeneity breaks pure local averaging!

**Federated averaging** (McMahan, Moore, Ramage, Hampson, y Arcas, AISTATS 2017) repeats:

1. The server broadcasts the current global model $$w_t$$ to a subset of clients $$\mathcal{S}_t$$.
2. Client $$c\in\mathcal{S}_t$$ runs $$E$$ local epochs of SGD on its *private* data, producing $$w_{t+1}^{(c)}$$.
3. The server sets

$$
w_{t+1} = \sum_{c\in\mathcal{S}_t} \frac{n_c}{n_{\mathcal{S}_t}} w_{t+1}^{(c)},
$$

where $$n_c$$ is the client’s example count and $$n_{\mathcal{S}_t}=\sum_{c\in\mathcal{S}_t}n_c$$.

If $$E=1$$ and each client takes one step on the *same* global batch size story, FedAvg collapses toward ordinary data-parallel SGD. The interesting (and statistically harder) regime is $$E>1$$: local drift on **heterogeneous** (non-IID) client distributions. Communication rounds become the iteration index that matters.

```python
def fedavg_round(client_models, client_sizes):
    n = sum(client_sizes)
    acc = 0.0
    for w_c, n_c in zip(client_models, client_sizes):
        acc = acc + (n_c / n) * w_c
    return acc
```

**Why devices.** Privacy, regulation, and bandwidth: you cannot ship every phone’s photos to a datacenter every night. FedAvg is a *pattern*, not a privacy proof — gradients and weights can still leak. Formal privacy (DP-SGD, secure aggregation) is a different course.
