Adding a single line—$$x_i \in \mathbb{Z}$$—to a linear program looks innocent on paper, yet it separates polynomial-time solvability from NP-completeness. At the same time, that single integrality constraint unlocks an extraordinary modeling language: binary variables $$z \in \{0, 1\}$$ turn logical rules, fixed setup costs, and "either-or" constraints into clean linear inequalities via big-$$M$$ formulations. Mastering the exact definition of MIPs and binary indicator tricks is the foundation of every discrete optimization model.

## Key ideas: Anatomy of Mixed Integer Programs and Binary Logic

![Quy hoạch Nguyên (IP) và Chiến lược Nhánh Cận]({{ site.baseurl }}/img/chapter_img/zero_fill/ch24_integer_programming_bnb.svg)

- **General MIP Taxonomy:** Depending on whether the underlying objective and constraints are linear, quadratic, or general convex, we obtain MILP (Mixed Integer Linear Program), MIQP, or MINLP. Pure integer programs restrict *all* variables to $$\mathbb{Z}$$; mixed integer programs allow continuous and discrete variables to coexist.
- **Binary Indicator Variables ($$z \in \{0, 1\}$$):** Binary variables act as algebraic switches. For example, $$z_1 + z_2 \le 1$$ encodes mutual exclusivity ("at most one of A or B"), while $$z_1 \le z_2$$ encodes logical implication ("if A is chosen, B must also be chosen").
- **Big-$$M$$ Linking Constraints:** To link a continuous flow $$x \ge 0$$ to a binary activation switch $$z \in \{0, 1\}$$, we write $$x \le M z$$ where $$M$$ is a valid upper bound on $$x$$. When $$z = 0$$, $$x$$ is forced to $$0$$; when $$z = 1$$, $$x \le M$$ is inactive.
- **Tightness of $$M$$ Matters:** Although any huge $$M$$ gives the same integer feasible set, an unnecessarily large $$M$$ weakens the continuous LP relaxation dramatically—making tight domain-specific bounds on $$M$$ one of the highest-leverage modeling skills in MIP.

### Worked example: Tight vs. Loose Big-$$M$$ Formulations

Suppose a factory decides whether to open a machine ($$z \in \{0, 1\}$$, fixed cost $$100$$) and how many units $$x \in [0, 10]$$ to produce, with constraint "$$x > 0 \implies z = 1$$". We want to minimize $$100 z - 15 x$$ when demand requires $$x = 4$$.

1. **Tight formulation ($$M = 10$$, exact capacity):** Constraint is $$x \le 10 z$$.
   - At $$x = 4$$, the LP relaxation allows $$z = 4 / 10 = 0.4$$, giving LP lower bound $$100(0.4) - 15(4) = 40 - 60 = -20$$.
   - The true integer optimum has $$z = 1$$, giving $$100(1) - 15(4) = +40$$. Integrality gap $$= 40 - (-20) = 60$$.
2. **Loose formulation ($$M = 1000$$, lazy guess):** Constraint is $$x \le 1000 z$$.
   - At $$x = 4$$, the LP relaxation sets $$z = 4 / 1000 = 0.004$$, giving LP lower bound $$100(0.004) - 60 = -59.6$$.
   - Integrality gap balloons to $$40 - (-59.6) = 99.6$$!
3. **Takeaway:** Both formulations define the *exact same* integer feasible points, yet choosing the tightest valid $$M = 10$$ strengthens the relaxation lower bound by nearly $$40$$ units before the solver even branches once.

This section aims to explain the basic concepts for solving optimization problems through the mixed integer program approach.

## Problem definition

When some variables in an optimization model have the constraint of being integers, this is called an integer program.

>$$
>\begin{align}
>&\min_{x} && f(x) \\\\
>&\text{subject to } && x \in C \\\\
>&&&x_{j} \in \mathbb{Z}, j \in J
>\end{align}
>$$
>
>$$
>\begin{align}
>\text{where } f: \mathbb{R}^{n} \rightarrow \mathbb{R}, \quad C \subseteq \mathbb{R}^{n} \quad \text{and} \quad J \subseteq \{1, \dotsc, n\}.
>\end{align}
>$$

In the above expression, if $$J$$ satisfies the following, it is called a pure integer program.

$$
J = \{1, \dotsc, n\}
$$

Let us assume that both $$f$$ and $$C$$ discussed in this section are convex.

## Binary variables

Looking at some representative examples of integer programs, we can mention yes/no decision problems or logical values. In this case, we define the problem using binary variables and solve the problem to find values of 0 or 1 for the conditions.

The combinatorial optimization to be introduced next is directly associated with integer programming. This is because by utilizing binary variables, we can transform existing problems and solve them as new problems.

Combinatorial optimization problems are defined using the triple $$(N, \mathcal{F}, c)$$ representation.<br>

> * $$N$$ is a finite ground set<br>
> * $$\mathcal{F} \subseteq 2^{N}$$ is the set of feasible solutions<br>
> * $$c \in \mathbb{R}^{N}$$ is the cost function<br>

The ultimate goal is to solve the following equation through the triple $$(N, \mathcal{F}, c)$$.

>$$
>\begin{align}
>\min_{S \in \mathcal{F}} & \sum_{i \in S} c_{i}
>\end{align}
>$$

Many combinatorial optimization problems can be formulated using binary integer programs.
